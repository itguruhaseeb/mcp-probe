# Baseline findings — mcp-probe conformance study (pilot run)

Generated by `benchmark/run-study.mjs` against the sample frame in
`benchmark/servers.json`. This is the **v0 baseline** run: a small, fully
reproducible pilot over the official reference servers plus a set of popular
community servers. It establishes the method and the first datapoints; the frame
is designed to expand in later runs (see STUDY.md, "longitudinal series").

- **Tool:** mcp-probe 0.1.0, client protocol `2025-06-18`
- **Runtime:** Node v25.6.1, servers launched via `npx -y <package>`
- **Credentials supplied:** none (per STUDY.md ethics)
- **Round-trip calls:** disabled for the ecosystem sweep (only the `everything`
  reference test server is round-trip-safe); no side-effecting tools were invoked.

## Sample frame outcome

| | count |
|---|---|
| Candidate servers attempted | 14 |
| **Included** (initialized without credentials) | **9** |
| Excluded — needs credentials | 4 (brave-search, slack, gitlab, google-maps) |
| Excluded — handshake failed | 1 (postgres — requires a connection-string argument) |

No server was dropped silently; every exclusion is recorded with a reason in
`records.json` and `summary.csv`.

## RQ1 — Conformance

Across the 9 servers that initialized, **104 tools** were measured.

- **9 / 9** servers completed the `initialize` handshake and returned a tool list.
- **104 / 104 (100%)** tool `inputSchema` definitions are valid JSON Schema with
  **zero FAIL-level violations** (no missing schemas, no invalid `type`, no
  malformed `properties`/`required`).
- **63 / 104 (60.6%)** tools are *fully clean* — valid schema **and** no
  warning-level issues.

**Takeaway:** at the level of hard schema validity, the surveyed MCP servers are
strongly conformant. The "servers are riddled with broken schemas" hypothesis is
**not** supported by this sample. The interesting variance lives one level up, in
optional-but-recommended metadata (RQ2).

## RQ2 — Drift

- **Single dominant deviation:** *missing tool `annotations`* (the
  `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` metadata
  introduced in the 2025-03-26 spec revision). **41 / 104 tools (39%)** omit it.
- The gap is **server-level, not random.** Annotations are all-or-nothing per
  server: 6 of 9 servers annotate every tool; **3 servers annotate none** —
  `github` (26 tools), `taskmanager` (10), `sqlite-npx` (5).
- **Protocol-version fragmentation:** two versions are live in the wild —
  `2025-06-18` (8 servers) and the older `2024-11-05` (1 server: the official
  **`github-mcp-server`**). So an *official reference server* is simultaneously the
  one lagging the protocol version **and** missing annotations — a clean, concrete
  drift signal.
- **0 / 9** servers emitted non-JSON noise on stdout (stdio framing is respected).

**Why this matters (safety framing):** annotations are how a client/agent learns
*before calling* whether a tool is read-only or potentially destructive. A 39%
omission rate means a meaningful fraction of tools give an autonomous agent no
machine-readable signal about their side effects — a measurable, citable gap
between the spec's safety affordances and ecosystem adoption.

## RQ3 — Reliability (latency, pilot only)

Handshake round-trip across the 9 servers: **p50 ≈ 2.26 s, p95 ≈ 8.76 s**
(min 0.57 s, max 8.76 s). **Caveat:** these include first-run `npx` install cost
and are *not* a clean latency measurement; a hardened run must pre-install servers
and warm them first. Malformed-request behavior is out of scope for this baseline.

## Honest limitations

- **Small n (9 servers).** This is a pilot that proves the pipeline, not a
  population estimate. The headline percentages will move as the frame grows.
- **GitHub-visible, npm-launchable, credential-free servers only** — not
  representative of private/internal servers or those behind API keys.
- Latency is contaminated by install cost (see above).
- Single spec version as the client baseline (`2025-06-18`); results are tagged to
  it and to the run date.

## Reproduce

```bash
cd mcp-probe
node benchmark/run-study.mjs        # writes benchmark/results/
```

Outputs: `summary.json` (aggregates), `summary.csv` (per-server table),
`records.json` (classified records), `raw/<id>.json` (full per-server probe output).
