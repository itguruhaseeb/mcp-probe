# Baseline findings — mcp-probe conformance study

Generated by `benchmark/run-study.mjs` against the sample frame in
`benchmark/servers.json`. This is the **v1 run** (n=16): the frame was expanded
from the initial 9-server v0 pilot to a 24-candidate frame spanning the official
reference servers plus a broader set of popular community servers. It establishes
the method and a longitudinal datapoint; the frame is designed to keep expanding
(see STUDY.md, "longitudinal series").

- **Tool:** mcp-probe 0.1.0, client protocol `2025-06-18`
- **Runtime:** Node v25.6.1, servers launched via `npx -y <package>`
- **Credentials supplied:** none (per STUDY.md ethics)
- **Round-trip calls:** disabled for the ecosystem sweep (only the `everything`
  reference test server is round-trip-safe); no side-effecting tools were invoked.

## Sample frame outcome

| | count |
|---|---|
| Candidate servers attempted | 24 |
| **Included** (initialized without credentials) | **16** |
| Excluded — needs credentials | 4 (brave-search, slack, gitlab, google-maps) |
| Excluded — handshake failed | 4 (postgres, puppeteer, fetcher, webresearch — each needs a required argument such as a connection string or target URL) |

No server was dropped silently; every exclusion is recorded with a reason in
`records.json` and `summary.csv`.

## RQ1 — Conformance

Across the 16 servers that initialized, **200 tools** were measured.

- **16 / 16** servers completed the `initialize` handshake and returned a tool list.
- **200 / 200 (100%)** tool `inputSchema` definitions are valid JSON Schema with
  **zero FAIL-level violations** (no missing schemas, no invalid `type`, no
  malformed `properties`/`required`).
- **117 / 200 (58.5%)** tools are *fully clean* — valid schema **and** no
  warning-level issues.

**Takeaway:** at the level of hard schema validity, the surveyed MCP servers are
strongly conformant. The "servers are riddled with broken schemas" hypothesis is
**not** supported by this sample, and the result held as the frame nearly doubled
from the v0 pilot (104→200 tools, 100%→100%). The interesting variance lives one
level up, in optional-but-recommended metadata (RQ2).

## RQ2 — Drift

- **Single dominant deviation:** *missing tool `annotations`* (the
  `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` metadata
  introduced in the 2025-03-26 spec revision). **83 / 200 tools (41.5%)** omit it.
- The gap is **strictly server-level, not random.** The split is all-or-nothing
  with **zero partial servers**: 8 servers annotate every tool
  (`everything`, `memory`, `sequential-thinking`, `filesystem`, `context7`,
  `playwright`, `desktop-commander`, `git`) and **8 annotate none**
  (`github` 26 tools, `playwright-ea` 33, `taskmanager` 10, `sqlite-npx` 5,
  `yt-transcript-sinco` 5, `quickchart` 2, `yt-transcript` 1, `commands` 1).
- **Protocol-version fragmentation (widened at larger n):** two versions are live
  in the wild — `2025-06-18` (12 servers) and the older `2024-11-05`
  (**4 servers**: `github`, `quickchart`, `yt-transcript`, `commands`). The official
  **`github-mcp-server`** is among the laggards, and is simultaneously on the old
  protocol version **and** annotating no tools — a clean, concrete drift signal.
- **0 / 16** servers emitted non-JSON noise on stdout (stdio framing is respected).

**Why this matters (safety framing):** annotations are how a client/agent learns
*before calling* whether a tool is read-only or potentially destructive. A 41.5%
omission rate means a meaningful fraction of tools give an autonomous agent no
machine-readable signal about their side effects — a measurable, citable gap
between the spec's safety affordances and ecosystem adoption. That the omission is a
clean server-level split (never partial) suggests it is a per-project authoring
decision, not per-tool oversight.

## RQ3 — Reliability (latency, pilot only)

Handshake round-trip across the 16 servers: **p50 ≈ 1.13 s, p95 ≈ 10.41 s**
(min 0.64 s, max 10.41 s). **Caveat:** these include first-run `npx` install cost
and are *not* a clean latency measurement; a hardened run must pre-install servers
and warm them first. Malformed-request behavior is out of scope for this baseline.

## Honest limitations

- **Still-modest n (16 servers).** Larger than the v0 pilot but not a population
  estimate. Headline percentages will keep moving as the frame grows.
- **GitHub-visible, npm-launchable, credential-free servers only** — not
  representative of private/internal servers or those behind API keys.
- Latency is contaminated by install cost (see above).
- Single spec version as the client baseline (`2025-06-18`); results are tagged to
  it and to the run date.

## Reproduce

```bash
cd mcp-probe
node benchmark/run-study.mjs        # writes benchmark/results/
```

Outputs: `summary.json` (aggregates), `summary.csv` (per-server table),
`records.json` (classified records), `raw/<id>.json` (full per-server probe output).
